
## 概述

本仓库用于存储一个ARM32嵌入式平台上从**Linux-5.15 LTS**​ 迁移至 **Linux-6.12 LTS**​ 的移植补丁、设备树修改、驱动适配笔记以及调试日志。

本工作基于供应商提供的 SDK。由于包含供应商专有代码，完整的原始 SDK 源码无法完全开源。

完整可用的 SDK 工程在本地维护，本仓库仅包含我的增量修改和文档。

这是我在前一个移植项目（从  **Linux-3.18**​ 迁移至 **Linux-5.15**）的后续工作。

## 环境

- **构建主机**：Ubuntu 22.04 LTS
- **硬件平台**：HI3798MV100
- **目标内核**：Linux 6.12.y LTS
- **交叉工具链**：仅内核 Bring‑up 阶段，复用原 5.15 SDK 中 Buildroot 生成的工具链GCC-12。
- **根文件系统（早期阶段）**：复用现有 5.15 Buildroot 根文件系统，仅用于内核/驱动调试。

> **注意**：早期复用的根文件系统可能存在 UAPI 头版本不匹配的风险，影响用户态程序。待内核与驱动移植完成后，将构建完全匹配的根文件系统。

## 仓库内容

- `patches/`：Git format‑patch 输出，包含基线的全部修改。目录内仍按 linux 内核目录组织
- `board_docs/`：移植笔记、API 变更记录、调试日志、测试报告。
- `LICENSES/`：分层许可文本（`GPL-2.0-only`、`CC BY-NC-ND 4.0`）。各目录的具体适用规则见下方「许可」章节。
- `README.md`：本文件。

## 如何复现

1. 在本地获取该平台的原始供应商 SDK。
2. 将 `patches/` 下的补丁集应用到 SDK 中。
3. **早期 Bring‑up**：使用现有的 5.15 交叉工具链编译 6.12 内核镜像与设备树，复用 5.15 根文件系统进行启动验证。
4. **内核/驱动移植完成后**：使用 `BR2_KERNEL_HEADERS=6.12` 重新构建完整的 Buildroot 根文件系统，进行全系统集成测试。

## 本地工作模式

本地磁盘上维护两个独立的完整 SDK 工程：

1. **HiSTB-515**：冻结的基线工程（linux-3.18→linux-5.15 移植成果）。保持完整不动，用于回归测试、验证、复现故障现象。
2. **HiSTB‑612**：独立的新工程，用于正在进行的 linux-5.15→linux-6.12 移植。直接在此修改内核、设备树及树外驱动，完全按linux-6.12架构要求，重构驱动程序源码。本地 Git 提交记录完整的开发历史。

本地完整的 SDK **不会**推送到 GitHub。仅将筛选后的、可公开的补丁和文档导出并更新到本仓库。
